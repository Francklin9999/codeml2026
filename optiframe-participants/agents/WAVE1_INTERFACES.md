# Wave-1 interfaces: what the modules really export

Read from the code (not the briefs) for briefs 10, 14, 15, 16, 17. Paths are under `app/src/`. Rule everywhere: only `OptiError` (`code: ErrorCode`) leaves a module; unknown exceptions are wrapped as `LOAD_FAILED`. Ten codes: NO_REFERENCE, REFERENCE_TILTED, BLURRY, NO_LENS, LENS_OUT_OF_WINDOW, GLARE, INCONSISTENT_SHOTS, LENS_ROTATED, CAMERA_DENIED, LOAD_FAILED. LENS_ROTATED is never thrown (see `rotationWarningDeg`); CAMERA_DENIED only by the live-camera path.

## Frames and units
- Photo px: centre of pixel (i, j) is at (i, j) (OpenCV). `Photo.image` is upright (EXIF applied) and already downscaled (side <= 4096, area <= 16 MP): H and all photo coordinates refer to THIS image, not the original file.
- Board frame: mm, origin = window top-left, x right, y down. `Rectified.image` is that window at `pxPerMm` = 10 (800x650 for 80x65 mm); pixel (i, j) covers [i, i+1)/10 mm.
- `Rectified.H` = board mm (physical: spec mm x `printScale`) -> PHOTO px, 9 numbers row-major (it is `invert3` of the fit photo->board). It is NOT a rectified-px matrix. Photo px of a board point: `applyH(H, [x, y])` (`vision/homography.ts`). Rectified px (i, j) centre <-> board mm ((i+0.5)/10, (j+0.5)/10). To draw `contourMm` on the rectified image use canvas coordinates `[x*pxPerMm, y*pxPerMm]`.
- `LensMeasurement.contourMm`, `boxCentre`: board frame, after parallax and bias (so a drawn overlay is off by the correction, about 0.5 mm when focal is known). A = extent along board x, B = extent along board y (axis-aligned, not rotated).
- Contours are counter-clockwise in the numeric y-down frame, i.e. POSITIVE shoelace (`measure/boxing.signedArea`), exactly 720 points (`N_POINTS`), last point not repeated. `fuseShots` also returns 720 points, same orientation.
- Right eye: nasal side is +x of the board; left eye: nasal side is -x (sheet labels "ŒIL DROIT : nez de ce côté" on the right).

## contracts.ts
`Pt=[number,number]`, `Eye='L'|'R'`, `PX_PER_MM=10`, `BoardSpec`, `Photo {image: ImageData; source:'camera'|'file'; focal35mm?}`, `Rectified {image,pxPerMm,H,reprojErrMm,sharpness,cameraDistMm?}`, `Mask {data:Uint8Array,width,height,method:'classic'|'model',score}` (1 = lens, same size as Rectified.image), `LensMeasurement {eye,contourMm,A,B,perimeter,boxCentre,method,quality{reprojErrMm,sharpness,nShots,spreadA,spreadB}}`, `FrameParams`, `DEFAULT_FRAME` (bridge 18, clearance 0.2, rim 3.5, thickness 4, lip 0.5, tenon {6, 8, hole 1.5}), `FrameResult {positions: Float32Array; indices: Uint32Array; seatL; seatR; gapMm}`, `ErrorCode`, `class OptiError(code, detail='')` (message = `CODE: detail`).

## capture/ (`capture/index.ts`; also `exif.ts parseExif`, `geometry.ts fitSize/orientationMatrix/MAX_SIDE/MAX_PIXELS`, not re-exported)
- `capturePhoto(opts: CaptureOptions = {}, env: CaptureEnv = browserEnv()): Promise<Photo>`: native camera sheet (`<input type=file capture=environment>`); `{useLiveCamera:true, waitForShutter?}` = getUserMedia path (CAMERA_DENIED on NotAllowed/Security error). Must be called from a user gesture.
- `pickFile(env?): Promise<Photo>`: gallery. `chooseOriginalFile(camera: boolean, env?): Promise<File>`: the untouched File (EXIF, focal length, bytes). `decodeFile(file: Blob, source: Photo['source'] = 'file', env?): Promise<Photo>`: decode + EXIF orientation + downscale + `focal35mm` from EXIF tag 0xA405.
- Errors: LOAD_FAILED for cancel ('cancelled'), no file, undecodable image; CAMERA_DENIED as above. Pitfalls: `focal35mm` is absent when EXIF lacks it, and always absent on the live-camera video-frame fallback, which silently disables the parallax correction and `cameraDistMm`. The 'cancel' event is not fired by older browsers: the promise then never settles. `decodeFile` reads only the first 256 KiB for EXIF.
- Exports also `browserEnv()`, `CaptureEnv` and `CaptureOptions` (test injection).

## vision/opencv.ts
- `loadOpenCv(): Promise<Cv>` (one shared promise, retry allowed after failure; rejects with `OptiError('LOAD_FAILED','opencv.js: ...')`). First call fetches `vendor/opencv/opencv.js` (13.3 MB) and evals it; in Node it `require`s node_modules (about 0.5 s measured on this PC; phones TO MEASURE). `setOpenCvUrl(u: string): void` overrides the URL and resets the cache (call before the first load). `evalOpenCv(source: string): unknown`. Types `Cv` (adds the ArUco API missing from the .d.ts).
- URL resolution (`defaultUrl`): `new URL(import.meta.env.BASE_URL ('./') + 'vendor/opencv/opencv.js', origin)` where origin = `document.baseURI` on the page, and in a worker (no `document`) `new URL('../', location.href)`. So the worker script MUST live one folder below the app root (built `assets/worker-*.js`, dev `/src/worker.ts`); a worker emitted elsewhere needs `setOpenCvUrl(absoluteUrl)` first. Node branch is taken only when `process.versions.node && !document` (jsdom tests use the fetch branch: avoid it).

## vision/rectify.ts
- `rectify(photo: Photo, spec: BoardSpec): Promise<Rectified>`: locate markers, fit, warp the window to 10 px/mm (Lanczos), measure sharpness. Throws NO_REFERENCE (fewer than 4 markers, or window outside the photo), REFERENCE_TILTED (corners not coplanar, `reprojErrMm > MAX_REPROJ_MM`, tilt > `MAX_TILT_DEG`), BLURRY, LOAD_FAILED. When NO_REFERENCE/REFERENCE_TILTED and the whole photo is blurred (`edgeWidthPx > MAX_EDGE_WIDTH_PX`), the code is BLURRY instead.
- `locateReference(photo, spec): Promise<Reference>` with `Reference {H, reprojErrMm, tiltDeg, cameraDistMm?, nMarkers, markerIds}`. `cameraDistMm` only when `photo.focal35mm` is set (tilt uses 26 mm if absent).
- Constants: `MAX_REPROJ_MM = 0.3`, `MAX_TILT_DEG = 35`, `MIN_SHARPNESS = 0.00015`, `MAX_EDGE_WIDTH_PX = 7.5`.
- Sharpness NOW (differs from older text): `referenceSharpness(cv, src: ImageData, spec, H: Mat3, markerIds: number[]): number` = median over the inlier reference markers of `patchSharpness(g: Uint8Array, w, h): number` (variance of the 4-neighbour Laplacian, noise-subtracted, divided by the squared 5-95 percentile spread, on 10 px/mm patches). Dimensionless, higher = sharper, independent of the window content. Crisp synthetic about 0.05; rig fixtures 0.00019 to 0.0015. `edgeWidthPx(cv, img: ImageData): number` is the marker-free fallback. Sharpness is NOT a distance: show it as a quality gauge only. `quality.test.ts` uses sharpness 100 as an arbitrary number.
- Gotchas: needs the sheet's markers on every photo (18 ArUco `DICT_4X4_50`); `spec.printScale` multiplies the board corners; the warped region is `spec.windowMm` (not scaled).

## vision/segmentClassic.ts
`segmentClassic(r: Rectified): Mask` is SYNCHRONOUS, pure typed arrays (no OpenCV), method 'classic', `score = min(1, rimContrast/0.5)`. Also exports `MIN_RIM_CONTRAST = 0.1`. Throws NO_LENS (rim contrast < 0.1, area outside 600..4000 mm2, bbox width outside 30..75 mm, solidity <= 0.9, no blob), LENS_OUT_OF_WINDOW (blob touches the border and is >= 15 mm), GLARE (> 5 % of the blob saturated, grey >= 250), LOAD_FAILED (bad image). Tries the dark-rim map, then a tinted-lens fallback (dark region). Scores of the classic and the model segmenters are not comparable.

## vision/segmentModel.ts
- `segmentModel(r: Rectified): Promise<Mask>` (method 'model', score = mean probability). `isModelAvailable(): Promise<boolean>` never rejects but really loads the model plus onnxruntime (fetch + session create): call it once, not per photo (a failure is not cached, so each call refetches). `getLastTimings(): Timings {loadMs, preMs, runMs, postMs}` (all 0 until a run succeeded). `setAssetBase(url: string | null): void` (absolute URL ending in `/`; resets the session). `setSessionForTests(s, loadTimeMs?)`.
- Asset root: `assetBase`, else `document.baseURI`, else (worker) `new URL('../', location.href)`: same one-folder-below rule as OpenCV. Model URL `models/lens_seg.onnx` (`MODEL_PATH`), ORT files `vendor/ort/` (`ORT_WASM_DIR`), single thread, wasm provider. A 200 answer with `text/html` (SPA fallback) counts as missing.
- Throws LOAD_FAILED (model missing, bad output size, runtime), NO_LENS (area outside 600..4000 mm2), LENS_OUT_OF_WINDOW (mask touches the border). Not called by `worker.ts` yet.
- Model contract: input `input` float32 `[1,3,320,384]` (NCHW, RGB, /255, mean (0.485,0.456,0.406), std (0.229,0.224,0.225)); output `logits` float32 `[1,1,320,384]` raw, sigmoid > 0.5 = lens. 800x650 -> 384x320 by plain bilinear, half-pixel centres, no anti-aliasing (`resizeBilinear`; training uses `cv2.INTER_LINEAR`). Exports also `preprocess`, `postprocess(logits, w, h, pxPerMm?)`, `largestComponent`, `fillHoles`, `MODEL_W/H`, `MEAN`, `STD`, `MASK_THRESHOLD`, `MIN/MAX_LENS_AREA_MM2`.

## measure/ (`measure/index.ts`)
- `measureLens(r: Rectified, m: Mask, eye: Eye): LensMeasurement` (synchronous). Pipeline: `contourFromMask` (outer edge of the dark band, sub-pixel, 60-harmonic low-pass) -> `parallaxCorrect` -> `biasCorrect` -> `boxing`. `nShots` 1, spreads 0. Throws NO_LENS (mask empty, < 100 mm2, bias gives size <= 0), LENS_OUT_OF_WINDOW, LOAD_FAILED (mask and image sizes differ).
- Parallax: scales about the window centre by (D-3)/D (`EDGE_HEIGHT_MM = 3`) only when `r.cameraDistMm >= 100`. Otherwise no correction.
- Bias: `setBias(b?: Bias): void` (`Bias {a0,a1,b0,b1}`, a1 and b1 > 0 and finite else LOAD_FAILED; no argument = identity), `loadBias(url: string): Promise<void>` (fetch + setBias; LOAD_FAILED), `A' = a0 + a1*A`, `B' = b0 + b1*B`, applied by scaling the contour about its box centre. State is module-level PER JS REALM: setting it on the main thread does not affect the worker. `getBias()` and `Bias` live in `measure/correction.ts`, not in the index. To FIT a new bias, run measurements with identity bias, or the corrections compound.
- `rotationWarningDeg(m: LensMeasurement): number | null`: angle (0..90) of the minimum-area rectangle's long side to the board x axis when > 5 degrees and long/short > 1.1; the UI maps non-null to LENS_ROTATED. `extentAlong(contour: Pt[], theta: number): number`.

## quality/ (`quality/index.ts`)
- `fuseShots(shots: LensMeasurement[]): LensMeasurement`: 0 shots NO_LENS; 1 shot returns the same object; >= 3 shots drop outliers (|dev from median| > max(0.3, 2.5 x median deviation)); then spread of A or B > `MAX_SPREAD_MM = 0.6` or box centres further apart than `MAX_CENTRE_SHIFT_MM = 1.0` throws INCONSISTENT_SHOTS (2 shots: no outlier rejection). Result: median radius per 720 angles about the mean centre; `quality`: max reprojErr, MIN sharpness, nShots = kept, spreadA/B. Does not check that eyes or methods agree (takes `kept[0]`). Shots must share the board frame: do not move the lens or sheet.
- `messageFor(code: ErrorCode): string`: French sentence per code (unknown -> LOAD_FAILED text).

## frame/ (`frame/index.ts`; also `layout.ts layoutLenses`, `polygons.ts`)
- `generateFrame(left: LensMeasurement, right: LensMeasurement, p: FrameParams): Promise<FrameResult>`: argument order is (left, right) (`layoutLenses(rightContour, leftContour, p)` is right first). `loadManifold(): Promise<ManifoldToplevel>` (WASM from `vendor/manifold/manifold.wasm`, `document.baseURI` or worker `../`, Node finds its own). Throws LOAD_FAILED (invalid params: need bridge, rim, thickness, lip, tenon w/h/hole > 0, clearance >= 0, hole < thickness, w > 1), NO_LENS (non-finite or tiny contour, lens too small for the lip, result not one connected piece).
- Conventions: input contours are board-frame, y down. Layout (frame coordinates, y down): bridge centre x = 0, each box centre y = 0; right lens on the -x side with its max-x (nasal) edge at -bridge/2, left lens on +x with its min-x edge at +bridge/2. Bridge bar 4 mm high, centre 3 mm above y = 0 (`y = -3`). `seatR`, `seatL`: seat outlines (contour offset by `clearanceMm`) in FRAME coordinates (y down, same winding as the input), not in mesh coordinates; `gapMm` = `clearanceMm` (not the bridge width). Mesh: x as in the frame, y = -y_frame (y UP), z from 0 (print bed) to `thicknessMm`; layers back lip 25 % / groove 50 % / front lip 25 %; `positions` x,y,z mm, counter-clockwise outward triangles. Viewed from +z with x right and y up, the wearer's right lens is at -x. For a 2D overlay of the measured contours use `layoutLenses` on `contourMm` (translation only).

## export/ (`export/index.ts`)
- `contourToSvg(m: LensMeasurement): string`: units mm, `width="Wmm"`, prints 1:1; contour translated (never mirrored), y down, plus dashed A x B box, 50 mm scale bar and French labels ("Œil gauche"/"Œil droit" from `m.eye`). NO_LENS if empty or non-finite.
- `meshToStl(f: FrameResult): ArrayBuffer`: binary STL, mm, normals recomputed, positions copied unchanged (y up, z up). NO_LENS on non-finite or bad index.
- `measurementToJson(left: LensMeasurement, right: LensMeasurement, params: FrameParams, appVersion: string, date: string): string`: keys `app, appVersion, date, units:'mm', left, right, frameParams`; each lens has `eye,A,B,perimeter,boxCentre,method,quality,contourMm` (720 points). NO_LENS on NaN/Infinity.
- `saveBlob(data: BlobPart, filename: string, mime: string): void` (DOM, user gesture, revokes after 4 s). `FILE_NAMES = { svgLeft: 'contour-gauche.svg', svgRight: 'contour-droit.svg', stl: 'monture.stl', json: 'mesures.json' }`. `requireFinite` is in `export/check.ts`, not re-exported.

## worker.ts and swRegister.ts
- `worker.ts`: `WorkerRequest = { type:'measure'; photo: Photo; spec: BoardSpec; eye: Eye }`, `WorkerResponse = { ok:true; result: LensMeasurement } | { ok:false; code: ErrorCode }`, `handleMessage(msg): Promise<WorkerResponse>`. It runs `rectify` -> `segmentClassic` -> `measureLens` only: no bias, no model fallback, no fusion, no error detail (the `detail` text is dropped). The `onmessage` loop is wired only inside a real `WorkerGlobalScope`. The worker bundle must stay one folder below the app root (see OpenCV).
- `swRegister.ts`: `registerServiceWorker(): Promise<void>` (registers `./sw.js` after window load; `?nosw=1` unregisters and clears caches; never throws). `main.ts` calls it only when `import.meta.env.PROD`; `main.ts` is still the placeholder page (no `ui/`, no `pipeline.ts`, no `eval.html`, no `collect.html` yet).

## public/, service worker, Vite
- `board_spec.json` (identical to `rig/out/board_spec.json`): `dictionary 'DICT_4X4_50'`, `markerMm 15`, 18 markers ids 0..17 (corners TL,TR,BR,BL in board mm, negative outside the window), `windowMm {80,65}`, `guideLineYMm 32.5`, `rulerMm 100`, `printScale 1` (set by `rig/set_print_scale.py`, rejects outside 0.97..1.03). `bias.json` = identity `{a0:0,a1:1,b0:0,b1:1}`.
- `vendor/opencv/opencv.js`, `vendor/manifold/manifold.wasm`, `vendor/ort/ort-wasm-simd-threaded.{mjs,wasm}` (14.2 MB), `lightbox.html`, `manifest.webmanifest`. `models/` holds only a README: `lens_seg.onnx` is absent.
- `sw.js` (`VERSION = 'v3'`, cache `optiframe-v3`): install precaches `index.html`, `collect.html`, `eval.html` and the `./` assets each references, `./vendor/opencv/opencv.js` and `./vendor/manifold/manifold.wasm`. `/vendor/` is cache-first (bump VERSION when it changes); everything else, including `/models/`, is network-first with cache fallback; ort files and the model are cached on first online use; `board_spec.json` and `bias.json` are cached on first fetch.
- `vite.config.ts`: `base './'`; every top-level `*.html` of `app/` is an entry (`index.html` -> `main`, `eval.html` -> `eval`); `public/` files are copied as is; `worker.format 'es'`; resolve condition `onnxruntime-web-use-extern-wasm`; Vitest: node env, `src/**/*.test.ts` + `tests/**/*.test.ts`, setup file `src/test/setup.ts` (ImageData polyfill); a DOM test starts with `// @vitest-environment jsdom`.

## Data formats and training CLIs
- Rig fixtures `rig/out/fixtures/fixture_NN_<name>.{png,json}` (10 pairs, git-ignored, regenerate: `cd rig; .venv/Scripts/python make_board.py --fixtures`). PNG 1600x1200 grey content. JSON: `name, H` (9 numbers, board mm -> image px, same convention as `Rectified.H`), `imageSize [1600,1200]`, `shape ('ellipse'|'rounded_rect')`, `widthMm`, `heightMm` (outer size of the dark rim, axis-aligned in the board frame = ground truth for A and B), `centreMm`, `rimMm`, `rimGrey`, `fillGrey`, `backgroundGrey`, `tiltDeg`, `blurSigmaPx`, `noiseSigma`, `seed`. No EXIF, so no `focal35mm`: no parallax. Load with `pngjs` (`PNG.sync.read`) into `new ImageData(new Uint8ClampedArray(png.data), w, h)`, as `vision/rectify.fixtures.test.ts` does.
- `training/data/synth.py --n N [--out DIR] [--seed 0] [--bg-dir DIR]` writes `DIR/images/synthNNNNNN_0_synth.jpg`, `DIR/masks/*.png` (0/255), `DIR/index.csv` (`file,lensId,pos,cond,source=synth`); default `training/_local/synth`. `autolabel.py PHOTOS_DIR --spec board_spec.json [--out DIR] [--qc N] [--seed] [--max-shift 3.0]`: photos `<lensId>_<pos>_<cond>.jpg`, a group needs an `easy` shot, other photos of the group are rejected if the window moved > 3 px; writes `images/, masks/, index.csv (source=real), rejected.csv, qc/`; default `training/_local/real`. `split.py REAL/index.csv [SYNTH/index.csv ...] [--out split.csv] [--seed 0]` splits by lensId (synth always train); `file` column is relative to the common parent folder (`real/images/...`).
- `training/model` (run from that folder): `train.py --data --out --sources real|synth|both --epochs 40 --batch 16 --lr --weight-decay --encoder-weights imagenet|none --seed --workers --device` writes `best.pt`, `train_log.json`; `export.py --ckpt --out` writes `lens_seg.onnx`, `lens_seg.int8.onnx`, `export_report.json` (opset 17, parity < 1e-3); `evaluate.py --data --ckpt|--onnx --split test --out` writes `metrics.md/.json`. Default dataset `training/_local/dataset` (`images/, masks/, index.csv, split.csv`), default out `training/_local/model_out`; scripts refuse to write under `app/`. Model: U-Net, encoder `tu-mobilenetv3_small_100`.

## Open issues known after wave 1
- No real-photo validation anywhere: every threshold (`MAX_REPROJ_MM 0.3`, `MIN_SHARPNESS`, `MAX_EDGE_WIDTH_PX`, `MIN_RIM_CONTRAST`, `MAX_SPREAD_MM`, `MAX_CENTRE_SHIFT_MM`, tilt 35, default focal 26 mm, `EDGE_HEIGHT_MM 3`) comes from synthetic scenes or the 10 rig fixtures: TO MEASURE. Sharpness in particular is calibrated only on synthetic blur; the real blur that still gives a 0.1 mm rim is unknown.
- `public/models/lens_seg.onnx` is absent: `isModelAvailable()` is false, `segmentModel` throws LOAD_FAILED, and the classic segmenter is the only working one. The int8 file's behaviour in onnxruntime-web is unverified; model latency on phones TO MEASURE.
- `worker.ts` is still the brief-01 shape: no bias message, no model fallback, error detail dropped. Bias is per-realm state, so brief 10 must call `setBias` (or `loadBias`) inside the worker. `bias.json` is identity until brief 14 fits one on real data.
- Parallax needs `Photo.focal35mm` (EXIF); without it (live-camera frame fallback, stripped EXIF) edges are about 1 % too large at 300 mm camera distance (3 mm edge height), not corrected.
- The training pipeline has no merge step: `autolabel.py` and `synth.py` write separate folders, `split.py` writes `file` paths that do not match `index.csv` (the loader falls back to lensId), while `train.py`/`evaluate.py` expect ONE folder with `images/ masks/ index.csv split.csv`: merge by hand. `autolabel.py` uses OpenCV `findHomography` (no sub-pixel refinement, ignores `printScale`, window px with centre-at-integer so masks are 0.5 px (0.05 mm) off the app's convention) and its condition names `lamp1..3`, `color` (protocol) differ from `lampL/T/R`, `colour` (brief 17, `docs/COLLECTE_DONNEES.md`).
- Frame fit untested physically: the lens is trapped by lips on both faces (0.5 mm lateral lip, 0.2 mm clearance) so insertion relies on print flexibility; hinge tenon and pin fit unverified; the SVG/STL have not been printed or checked in a slicer on this repo.
- `LENS_ROTATED` exists only as a helper (`rotationWarningDeg`); A and B are axis-aligned extents, so a rotated lens is over-measured until the user realigns. Frame generation assumes the lens is placed with the correct nasal side (see Frames).
- Offline: ort and the model are cached only after one online use; a changed `models/lens_seg.onnx` needs a `VERSION` bump in `sw.js` (cache-first). `app/dist/` is stale (git-ignored build output, `sw.js` differs from `public/sw.js`): rebuild before trusting it.
- `capture`: no real phone test (iOS 'cancel' event, `createImageBitmap` orientation option, `ImageCapture`); `chooseOriginalFile` and `capturePhoto` need a user gesture.
